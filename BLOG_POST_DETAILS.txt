1. WHAT IS TRACEGUARD AI
--------------------------------------------------------------------------------

TraceGuard AI is an autonomous, agentic fraud investigation and next-best action
platform powered by TigerGraph Cloud, LangGraph, GraphRAG, FastAPI, and a Next.js 15
Cyber Command Center UI.

It operates as an intelligent force multiplier for fraud risk teams, continuously
analyzing transaction streams, mapping complex multi-hop entity relationships,
detecting sophisticated fraud rings, and issuing policy-governed action directives.


--------------------------------------------------------------------------------
2. PURPOSE OF TRACEGUARD AI
--------------------------------------------------------------------------------

Financial institutions face an accelerating wave of organized, cross-border fraud,
including Account Takeovers (ATO), synthetic identities, and high-velocity mule networks.

Traditional fraud investigation workflows are deeply flawed:
- Fragmented Systems: Analysts manually cross-reference transaction logs, device records,
  and customer PII across siloed relational databases.
- High Latency: Tracing multi-hop money trails takes hours or days, by which time stolen
  funds have already exited the ecosystem.
- Decision Fatigue & Compliance Risk: Manual SAR filing and risk scoring are prone to
  human error and policy oversights.

The purpose of TraceGuard AI is to automate the entire investigation lifecycle—moving
from uncertain, noisy fraud triggers to defensible, audit-compliant action directives
in sub-seconds while preserving human-in-the-loop analyst governance.


--------------------------------------------------------------------------------
3. WHAT WE BUILT
--------------------------------------------------------------------------------

We built a end-to-end, production-ready platform that automates the fraud lifecycle:

- Automated Trigger Ingestion: Listens for risk signals, velocity spikes, customer
  reports, or manual analyst audits.
- Deep Graph Retrieval: Executes multi-hop graph traversals on TigerGraph Cloud to
  uncover shared hardware, proxy IP clusters, and counterparty paths.
- Typology Pattern Detection: Automatically detects 4 primary fraud patterns:
  Device Sharing Rings, Rapid Asset Movement, Account Takeover, and Structuring.
- Uncertainty & Evidence Demand: Computes Risk Score vs. Confidence Weight; automatically
  requests policy-approved step-up authentication when uncertainty is high.
- Next-Best Action Directives: Recommends policy-governed actions (Block Account,
  File SAR, Step-Up Auth, Escalate).
- Human-in-the-Loop Governance: Enforces analyst approval workflows for high-impact actions.
- Explainable Dossier Generation: Generates complete, transparent reasoning summaries and
  writes investigation outcomes back into graph memory.


--------------------------------------------------------------------------------
4. SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------

TraceGuard AI is built on a modular, microservice-friendly architecture:

[ User Interface Layer ]
  └─ Next.js 15 App Router & Tailwind CSS (Cyber Command Center UI)
  └─ Real-time Dashboard | Case Docket Queue | Interactive Cockpit | Graph Viewer

[ API Orchestration Layer ]
  └─ FastAPI Core Service (Python 3.11+)
  └─ REST endpoints (/api/v1/cases, /transactions, /investigations, /graph, /benchmark)
  └─ Dual-source database abstraction (TigerGraph Cloud + SQLite caching)

[ Agentic Reasoning Layer ]
  └─ LangGraph 8-Node State Machine Agent Workflow
  └─ State nodes: Investigate -> Collect Evidence -> Detect Patterns -> Assess Risk
     -> Recommend Action -> Policy Guard -> Generate Explanation -> Save Memory

[ Knowledge & Context Layer (GraphRAG) ]
  └─ Policy & Regulatory Rule Store (SAR filing rules, velocity thresholds)
  └─ Typology Engine & Historical Case Memory RAG

[ Graph Storage & Analytics Layer ]
  └─ TigerGraph Cloud (`TraceGuardGraph`)
  └─ GSQL Installed Queries: `findSharedDevices`, `getCaseNetwork`
  └─ pyTigerGraph & RESTPP Token Authentication


--------------------------------------------------------------------------------
5. HOW TIGERGRAPH IS USED
--------------------------------------------------------------------------------

Relational databases fail at scale when traversing complex multi-hop relationships.
TigerGraph serves as the core relational graph engine for TraceGuard AI:

1. Schema Topology (`TraceGuardGraph`):
   - Primary Vertex: `PaymentTransaction` (amount, timestamp, risk_score, sender, receiver)
   - Secondary Vertices: `Account`, `Customer`, `Device`, `IP`, `Case`
   - Edges: `INITIATED`, `USED_DEVICE`, `FROM_IP`, `ASSOCIATED_WITH`, `OWNED_BY`

2. Custom GSQL Installed Queries:
   - `findSharedDevices`: Traverses target account -> transactions -> devices
     -> other transactions -> connected accounts to expose device-sharing rings instantly.
   - `getCaseNetwork`: Extracts a 3-hop local subgraph around any case/transaction
     including connected hardware, IP addresses, and counterparty nodes.

3. RESTPP Integration & Performance:
   - Secure token authentication over TigerGraph RESTPP endpoints.
   - Converts raw graph JSON returns into normalized GraphData DTOs for 2D/3D visualization.


--------------------------------------------------------------------------------
6. THE AGENTIC CAPABILITIES IMPLEMENTED
--------------------------------------------------------------------------------

TraceGuard AI implements an 8-node LangGraph state machine:

1. Investigate Node: Initializes case state from incoming risk signals or customer alerts.
2. Collect Evidence Node: Invokes TigerGraph MCP tools to retrieve multi-hop relationships.
3. Detect Patterns Node: Analyzes graph evidence for Device Sharing Rings, Rapid Velocity, ATO, and Structuring.
4. Assess Risk & Uncertainty Node: Calculates dynamic risk score (0-100) and confidence score.
   If uncertainty is high, flags the need for additional evidence.
5. Recommend Next-Best Action Node: Formulates defensible directives (e.g. BLOCK_ACCOUNT,
   FILE_REPORT, STEP_UP_AUTH, ESCALATE).
6. Policy Guardrail Node: Evaluates directives against institutional policy rules.
   High-impact actions are flagged for mandatory human approval.
7. Generate Explanation Node: Produces complete, human-readable reasoning dossiers.
8. Save Memory Node: Persists findings, decisions, and outcomes into case memory.


--------------------------------------------------------------------------------
7. WHAT WE LEARNED
--------------------------------------------------------------------------------

1. Graph Topology Is Essential for Fraud Detection:
   A single transaction may look completely normal in isolation, but when connected to a
   device shared across 4 flagged accounts, the fraud ring becomes obvious instantly.

2. Combining GraphRAG with Policy Engines Eliminates Hallucinations:
   Unconstrained LLMs risk making illegal or unauthorized decisions. Grounding the agent
   with GraphRAG policy context and enforcing hard policy guardrails ensures 100% compliance.

3. Analyst-First Governance Drives Adoption:
   AI agents succeed when they assist analysts rather than replacing them. Clear
   explainability and interactive approval controls build immediate trust with fraud ops teams.
